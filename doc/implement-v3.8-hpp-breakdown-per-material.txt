KONTEKS & MOTIVASI

HPP Breakdown yang dikembalikan ke iOS (latest_hpp_breakdown) saat ini hanya menyimpan
5 angka agregat: fabric, pooled_material, hardware, labor, overhead.

Untuk produk multi-kain seperti Pouch (Waffle Blue + Linen Putih + Dakron), angka
"Kain: Rp3.025" tidak menjelaskan kontribusi per kain. User tidak tahu apakah Waffle
lebih mahal dari Linen, atau berapa Dakron per piece.

Hal yang sama berlaku untuk hardware — satu angka "Hardware: Rp500" tidak menjelaskan
"Ring D Rp200 + Karet Elastis Rp300".

Solusi v3.8: tambah fabric_items dan hardware_items ke shape HppBreakdownOut.
Tidak ada schema migration — semua data sudah tersedia di tabel yang ada.

1. PYDANTIC SCHEMA

Tambah struct baru HppLineItemOut (di file yang sama dengan HppBreakdownOut):

    class HppLineItemOut(BaseModel):
        name: str
        cost: float

Update HppBreakdownOut — tambah dua field dengan default []:

    class HppBreakdownOut(BaseModel):
        fabric: float
        fabric_items: list[HppLineItemOut] = []   # NEW
        pooled_material: float
        hardware: float
        hardware_items: list[HppLineItemOut] = []  # NEW
        labor: float
        overhead: float
        total: float

Default [] memastikan backward compat untuk consumer lama.

2. LOGIC — fabric_items

Sumber data: production_batch_layout → cutting_layout → cutting_layout_item
             → material_purchase → material.name + cutting_layout_item.cost_per_piece

Pseudocode (sesuaikan dengan ORM/query pattern yang sudah ada di codebase):

    def _get_fabric_items(db, batch_id: UUID, product_size_id: UUID) -> list[HppLineItemOut]:
        layouts = (
            db.query(ProductionBatchLayout)
            .filter(ProductionBatchLayout.production_batch_id == batch_id)
            .order_by(ProductionBatchLayout.sort_order)
            .all()
        )
        items = []
        for pbl in layouts:
            layout = pbl.cutting_layout
            cli = (
                db.query(CuttingLayoutItem)
                .filter(
                    CuttingLayoutItem.cutting_layout_id == layout.id,
                    CuttingLayoutItem.product_size_id == product_size_id,
                )
                .first()
            )
            if cli is None:
                continue
            material_name = layout.material_purchase.material.name
            items.append(HppLineItemOut(name=material_name, cost=cli.cost_per_piece))
        return items

Catatan:
- cost_per_piece di CuttingLayoutItem adalah per-piece rate (sudah dibagi qty_suggested).
  Ini yang benar — HppBreakdown adalah per-unit cost, bukan total.
- Gunakan eager loading (selectinload/joinedload) jika ada N+1 risk.
- Jika product_size_id tidak match di layout manapun (e.g. manual batch), return [].

3. LOGIC — hardware_items

Sumber data: PatternSpec aktif untuk product_size_id → components (hardware only)
             × material.current_avg_cost

BUKAN snapshot historis — ini current cost (approximate). Catat di komentar kode.

    def _get_hardware_items(db, product_size_id: UUID) -> list[HppLineItemOut]:
        spec = (
            db.query(PatternSpec)
            .filter(
                PatternSpec.product_size_id == product_size_id,
                PatternSpec.is_active == True,
            )
            .order_by(PatternSpec.effective_from.desc())
            .first()
        )
        if spec is None:
            return []

        items = []
        for component in spec.components:
            mat = component.material
            # Filter sama dengan _hardware_cost_per_unit (lihat production.py)
            if mat.category != "hardware" or mat.cost_class != "direct_precise":
                continue
            if not mat.current_avg_cost:
                continue
            cost = round(component.qty_per_unit * mat.current_avg_cost, 2)
            items.append(HppLineItemOut(name=mat.name, cost=cost))

        return items

4. INTEGRASI

Di fungsi yang build HppBreakdownOut (temukan dulu di kode aktual), tambah dua field:

    fabric_items=_get_fabric_items(db, batch_id, product_size_id),

Pastikan perubahan berlaku di SEMUA tempat yang return HppBreakdownOut:
- GET /products/{sku}/sizes (list)
- GET /products/{sku}/sizes/{size_id} (detail)
- Jika ada endpoint lain yang return hpp breakdown, update juga

---

5. EDGE CASES

- 1 kain saja: fabric_items berisi 1 entry. Frontend tampilkan sub-rows hanya
  jika count > 1 — data tetap dikembalikan untuk konsistensi.
- Belum pernah produksi (latest_hpp_breakdown = null): tidak berubah, null tetap null.
- Manual batch (tanpa cutting layout): _get_fabric_items return [] → fabric_items = [].
- PatternSpec tidak ditemukan: hardware_items = [].
- material.current_avg_cost = 0 atau None: skip item, jangan return cost: 0.
