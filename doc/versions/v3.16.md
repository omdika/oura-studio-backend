## Behavior Endpoint yang Perlu Dikonfirmasi

### `POST /products/{sku}/sizes`

Frontend v3.16 akan memanggil endpoint ini saat user save resep Varian Kain untuk fabric yang belum punya ProductSize tersendiri. Sebelum memanggil, iOS sudah cek di list existing sizes — jadi call ini hanya terjadi jika variant memang belum ada.

Namun perlu konfirmasi: **apa yang terjadi jika `(product_id, size_label, fabric_variant_name)` sudah ada di database?**

- **Skenario A (aman):** Backend return 409 Conflict → iOS tidak akan memanggil karena sudah cek lebih dulu, tidak masalah.
- **Skenario B (lebih baik, nice-to-have):** Backend return 200 dengan existing record (upsert) → iOS tidak perlu pre-check, lebih simple.

Jika saat ini backend return 409 (Skenario A), tidak perlu diubah — iOS menghindarinya dengan lookup terlebih dahulu.

Jika ingin Skenario B sebagai improvement:
```python
# Di endpoint POST /products/{sku}/sizes
# Setelah validasi:
existing = db.query(ProductSize).filter(
    ProductSize.product_id == product.id,
    ProductSize.size_label == body.size_label,
    ProductSize.fabric_variant_name == body.fabric_variant_name,
).first()
if existing:
    return existing  # 200 dengan existing record — idempotent
# ... lanjut create baru
```
