## Ringkasan

v3.17 menambahkan satu endpoint baru untuk lookup `ProductSize` berdasarkan UUID langsung, tanpa perlu tahu SKU produknya. Endpoint ini digunakan iOS segera setelah berhasil decode QR code.

## Endpoint Baru

### `GET /product-sizes/{size_id}`

Lookup satu ProductSize berdasarkan ID, tanpa perlu tahu SKU.

**Mengapa endpoint ini diperlukan:**
QR code hanya mengkodekan `productSizeId` (UUID). Saat scan, iOS tidak tahu SKU-nya — tidak bisa memanggil `GET /products/{sku}/sizes/{id}` yang sudah ada. Endpoint ini menjadi single-lookup yang mengembalikan semua data yang diperlukan untuk kedua flow (jual dan stok masuk).

**Path parameter:**
- `size_id` (UUID) — ID dari product_size yang dicari

**Response (200 OK):**

Shape identik dengan item dari `GET /products/{sku}/sizes` — sudah ada di iOS sebagai `ProductSizeDetail`. Backend tinggal reuse query + serializer yang sama, hanya diekspos via route berbeda.

```json

  "product_id": "...",
  "product_sku": "SCRMINI",
```

**Error responses:**

| Kode | Kasus |
|---|---|
| 404 | `size_id` tidak ditemukan di tabel `product_sizes` |
| 422 | `size_id` bukan UUID valid |

**SQL query dasar** (sesuaikan dengan ORM yang dipakai):

```sql
SELECT
  ps.id,
  ps.product_id,
  p.sku          AS product_sku,
  p.name         AS product_name,
  ps.size_label,
  ps.fabric_variant_name,
  ps.reorder_min_qty,
  ps.is_archived,
  ps.selling_price,
  -- stock aggregation sama seperti di GET /products/{sku}/sizes
  COALESCE(stock.current_stock_qty, 0)    AS current_stock_qty,
  COALESCE(stock.production_stock_qty, 0) AS production_stock_qty,
  COALESCE(stock.manual_stock_qty, 0)     AS manual_stock_qty,
  -- latest HPP dari production batch, sama seperti endpoint existing
  hpp.breakdown AS latest_hpp_breakdown,
  hpp.margin_pct
FROM product_sizes ps
JOIN products p ON p.id = ps.product_id
LEFT JOIN (...stock aggregation subquery...) stock ON stock.product_size_id = ps.id
LEFT JOIN (...latest HPP subquery...) hpp ON hpp.product_size_id = ps.id
WHERE ps.id = :size_id
```

**Catatan implementasi:**
- Query ini sudah ada di `GET /products/{sku}/sizes` — cukup ekstrak ke helper function / repository method dan panggil dari kedua route.
- Tidak perlu filter `is_archived = false` — iOS akan tampilkan pesan "varian ini sudah dinonaktifkan" berdasarkan field `is_archived` di response.
- Jika tidak ada `latest_hpp_breakdown` (belum pernah diproduksi), kembalikan `null` — iOS sudah handle ini.

## Route Registration

Pastikan route `/product-sizes/{size_id}` didaftarkan **sebelum** route yang lebih generik jika ada. Tidak ada konflik yang diperkirakan dengan route `/products/{sku}/sizes` karena prefix berbeda.

Contoh FastAPI:
```python
@router.get("/product-sizes/{size_id}", response_model=ProductSizeDetailOut)
async def get_product_size_by_id(
    size_id: UUID,
    db: AsyncSession = Depends(get_db),
    current_user = Depends(get_current_user),
):
    size = await product_size_repo.get_by_id(db, size_id)
    if not size:
        raise HTTPException(status_code=404, detail="Product size not found")
    return size
```
