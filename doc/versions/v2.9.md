# v2.9 — Sizes List Field Spec: Frontend Requirement Clarification (2026-08-08)
**Date:** 2026-08-08  
**Changed by:** Frontend (spec update — backend action required → resolved in v2.10)  
**Status:** ✅ RESOLVED in v2.10

---

## Summary

Frontend melaporkan bahwa `GET /products/{sku}/sizes` masih kurang beberapa field yang dibutuhkan untuk RINCIAN HPP dan stock breakdown di iOS. Ini adalah spec clarification dari Frontend, bukan bug fix.

---

## Fields yang Diminta

```json
{
  "id": "uuid",
  "product_id": "uuid",
  "size_label": "M",
  "fabric_variant_name": "Satin Pelangi",
  "reorder_min_qty": 20.0,
  "selling_price": 22000.0,
  "is_archived": false,
  "current_stock_qty": 12,
  "production_stock_qty": 12,
  "manual_stock_qty": 0,
  "latest_hpp_breakdown": {
    "fabric": 3400.0,
    "pooled_material": 350.0,
    "hardware": 120.0,
    "labor": 2800.0,
    "overhead": 600.0,
    "total": 7270.0
  },
  "margin_pct": 0.67
}
```

Catatan kunci:
- `latest_hpp_breakdown` keys harus `fabric`, `pooled_material`, `hardware`, `labor`, `overhead`, `total` — bukan nama kolom DB (`hpp_fabric`, dll)
- `production_stock_qty` = sum stock_ledger WHERE reason='production'
- `manual_stock_qty` = sum stock_ledger WHERE reason IN ('initial', 'adjustment')
- Semua field ini juga harus ada di PATCH dan POST sizes responses (shared `ProductSizeOut` base)

---

## Conflict Resolution

v2.4 menyatakan `production_stock_qty`/`manual_stock_qty` tidak diperlukan. v2.9 membuka kembali karena iOS memerlukan stock-source breakdown untuk ProdukSizeDetailView. Keputusan: ship karena iOS mendeklarasikannya sebagai `Int?` (nil → 0) sehingga tidak crash tanpa field ini. Diimplementasikan di v2.10.
