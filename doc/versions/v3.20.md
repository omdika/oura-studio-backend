## Item Pending dari Session Sebelumnya

### 1. addStockFromBahan — Investigasi 404

**Endpoint:** `POST /products/{sku}/sizes/{size_id}/stock-from-bahan`

**Symptom:** Mengembalikan 404 sehingga frontend fallback ke `adjustStock` biasa.
Bahan tidak dikurangi saat user scan QR → "Dari Produksi" → toggle ON → Simpan.

**Langkah debugging ada di:** `doc/fix-stock-from-bahan.txt`

Kemungkinan penyebab:
- URL path di router tidak match (routing issue)
- Handler lookup spec berdasarkan `spec_id` tapi tidak menemukan record
- Validasi `spec.product_size_id == size_id` gagal untuk produk tanpa varian kain

**Catatan frontend:** Tidak perlu perubahan frontend setelah fix — frontend sudah coba
endpoint ini terlebih dulu, lalu fallback ke `adjustStock` jika dapat 4xx. Setelah
endpoint berjalan, fallback tidak dieksekusi dan warning kuning tidak muncul lagi.

### 2. MaterialUsageLog — Catat Deduction Kain dari QR Scan

**Symptom:** Tab "Pergerakan Stok" di BahanDetailView tidak menampilkan pengurangan kain
yang terjadi saat `addStockFromBahan` berhasil.

**Root cause:** `GET /materials/{id}/usage` hanya membaca dari `cutting_layout_item`
(CuttingLayout yang status='used', dari batch produksi). Deduction dari `addStockFromBahan`
tidak dicatat di tabel apapun yang dibaca endpoint tersebut.

**Fix yang dibutuhkan:**
Saat `addStockFromBahan` berhasil, catat deduction ke tabel logging (bisa
`material_usage_log` baru atau extend `stock_ledger` untuk material):

```python
# Contoh — sesuaikan dengan model yang ada
for fabric in spec.fabrics:
    deduct_cm = fabric.cut_length_cm * qty
    # Catat ke log — GET /materials/{id}/usage harus baca dari sini
    usage_entry = MaterialUsageLog(
        material_id=fabric.material_id,
        deducted_cm=deduct_cm,
        source="qr_scan",
        product_size_id=size_id,
        created_at=utcnow()
    )
    db.add(usage_entry)
```

Pastikan `GET /materials/{id}/usage` juga query dari tabel ini (bukan hanya
`cutting_layout_item`).

**Catatan:** Jika tabel `material_usage_log` belum ada, perlu migration. Jika
ada alternatif (extend `cutting_layout_item` atau tabel lain), sesuaikan.

### 3. Multi-fabric FIFO untuk addStockFromBahan

**Symptom:** `addStockFromBahan` saat ini (jika sudah fix routing) mungkin hanya
deduct dari satu fabric atau tidak handle multi-fabric spec dengan benar.

**Fix:** Loop semua `spec.fabrics`, untuk setiap fabric lakukan FIFO deduction dari
`material_purchase` yang paling lama (oldest first):

```python
for fabric in spec.fabrics:
    total_deduct_cm = fabric.cut_length_cm * qty
    purchases = db.query(MaterialPurchase).filter(
        MaterialPurchase.material_id == fabric.material_id,
        MaterialPurchase.remaining_length_cm > 0
    ).order_by(MaterialPurchase.purchase_date.asc()).all()

    remaining = total_deduct_cm
    for purchase in purchases:
        deduct = min(purchase.remaining_length_cm, remaining)
        purchase.remaining_length_cm -= deduct
        remaining -= deduct
        if remaining <= 0:
            break
```

Ini sama dengan FIFO yang sudah dilakukan di `POST /cutting-optimizer/layouts/confirm`.
