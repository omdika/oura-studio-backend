# Version 3.48 - Integrasi Login Google SSO (Spesifikasi Teknis)

## 1. Problem / Opportunity
*   **Context:** Saat ini, sistem otentikasi di aplikasi iOS Oura Studio menggunakan data mock (`MockAPIService`) untuk Google Sign-In atau mewajibkan penulisan Bearer Token secara manual dalam mode debug (`loginWithDevToken`). Backend sesungguhnya sudah memiliki basis schema untuk tabel `owner_account`, namun integrasi end-to-end Google SSO secara aman dan production-ready belum terkonfigurasi.
*   **Objective:** Menyusun rencana arsitektur dan spesifikasi kebutuhan untuk mengintegrasikan Google Single Sign-In (SSO) secara native pada aplikasi iOS (frontend) dan FastAPI (backend), dengan fokus pada:
    1.  Login langsung ke aplikasi menggunakan `ASWebAuthenticationSession` dengan skema Reversed Client ID (menghindari static web intermediary).
    2.  Penyimpanan Google Client ID secara aman di `Info.plist`.
    3.  Verifikasi token secara offline di backend FastAPI menggunakan pustaka `google-auth` untuk efisiensi dan keamanan maksimal.

---

## 2. User Flow & UX Specifications
*   **Entry Point:** Layar login (`LoginView`) yang muncul otomatis ketika `appState.isAuthenticated == false`.
*   **UI Components:** 
    *   **"Masuk dengan Google" Button:** Menggunakan komponen kustom `GoogleGIcon` dengan gaya modern sesuai panduan visual Google (Google Branding Guidelines).
    *   **Loading State:** `ProgressView` sirkuler muncul menggantikan ikon Google dan teks tombol saat otentikasi sedang berlangsung untuk memberikan umpan balik interaktif.
    *   **Error Banner:** Banner merah estetik menggunakan `OuraTheme.Colors.dangerBg` & `dangerText` yang muncul secara dinamis di atas tombol login jika terjadi kegagalan sistem atau otentikasi ditolak (403/401).
*   **User Journey (Direct SSO):**
    1.  User mengetuk tombol **"Masuk dengan Google"**.
    2.  Aplikasi membuka lembar web secure native melalui `ASWebAuthenticationSession` yang mengarah langsung ke `accounts.google.com`.
    3.  User memilih akun Google mereka dan memberikan izin akses profil dasar & email.
    4.  Google mengalihkan hasil autentikasi kembali menggunakan custom URL scheme berbasis **Reversed Client ID** (`com.googleusercontent.apps.xxxx:/oauth2callback`).
    5.  Aplikasi menangkap lembar redirect tersebut secara internal, mengekstrak parameter `id_token` dari URL fragment, dan menutup lembar web secara mulus.
    6.  Aplikasi mengirimkan `id_token` ke backend (`POST /auth/google`).
    7.  Setelah sukses, backend mengembalikan JWT token, aplikasi menyimpannya ke Keychain, dan transisi layar utama (`MainTabView`) terjadi tanpa kedipan layar (smooth fade-in).

## 3. Database Schema (FastAPI / SQLAlchemy)
Tabel otentikasi di PostgreSQL/Supabase didesain minimalis karena hak akses aplikasi ini bersifat *single-owner* (aplikasi pemilik tunggal):

```sql
CREATE TABLE owner_account (
    id          UUID PRIMARY KEY,
    google_sub  TEXT NOT NULL UNIQUE,   -- ID unik stabil milik Google ('sub' claim dari verified ID token)
    email       TEXT NOT NULL UNIQUE,   -- Disimpan untuk pencatatan/log saja, bukan kunci pencarian utama
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### Aturan Bisnis Penyediaan Akun (Provisioning Rules):
1.  **First-time Provisioning:** Saat email pemilik yang sukses login dari Google cocok dengan `AUTHORIZED_OWNER_EMAIL` di environment backend, data `google_sub` dan `email` akan di-*insert* secara otomatis ke tabel `owner_account`.
2.  **Subsequent Logins:** Untuk login berikutnya, backend akan melakukan verifikasi bahwa `google_sub` dari ID Token Google baru cocok dengan `google_sub` yang sudah terdaftar di database. Hal ini mencegah pengambilalihan akun jika alamat email Google diubah atau dikloning di masa mendatang.

## 4. API Contract (FastAPI)

### **POST /api/v1/auth/google**
Endpoint publik tanpa otentikasi Bearer Token untuk menukar ID Token Google dengan JWT Token internal aplikasi.

*   **Request Body:**
    ```json
    {
      "id_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6..."
    }
    ```

*   **Response (200 OK):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "expires_at": "2026-10-03T15:00:00Z"
    }
    ```

*   **Error Responses:**
    *   `400 Bad Request` (Token kosong atau salah format).
    *   `401 Unauthorized` (Token Google kadaluarsa atau tanda tangan tanda pengenal tidak valid).
    *   `403 Forbidden` (Email Google tidak cocok dengan `AUTHORIZED_OWNER_EMAIL`, atau `google_sub` tidak cocok dengan pemilik terdaftar).

### **Langkah Verifikasi Offline di Backend (FastAPI):**
Backend harus memproses verifikasi token secara offline (tanpa memanggil HTTP request tambahan ke Google setiap kali login) dengan alur berikut:
1.  Unduh dan cache kunci publik Google (`https://www.googleapis.com/oauth2/v3/certs`) secara berkala atau gunakan pustaka internal.
2.  Verifikasi JWT signature dari `id_token` menggunakan kunci publik Google.
3.  Verifikasi bahwa klaim `aud` (Audience) di dalam token cocok dengan `GOOGLE_CLIENT_ID` (iOS client ID) yang dikonfigurasi di backend.
4.  Verifikasi klaim `iss` (Issuer) cocok dengan `https://accounts.google.com` atau `accounts.google.com`.
5.  Pastikan waktu `exp` (Expiration) belum terlampaui.
6.  Gunakan modul `google.oauth2.id_token` di Python:
    ```python
    from google.oauth2 import id_token
    from google.auth.transport import requests

    try:
        # Menjalankan verifikasi offline dan validasi masa aktif
        id_info = id_token.verify_oauth2_token(
            token_string, 
            requests.Request(), 
            audience=os.environ.get("GOOGLE_CLIENT_ID")
        )
        
        # Ekstrak data klaim google
        google_sub = id_info['sub']
        email = id_info['email']
        
    except ValueError as e:
        raise HTTPException(status_code=401, detail="Token Google tidak valid")
    ```

## 5. Frontend & iOS Specifications (SwiftUI)

### **A. Konfigurasi `Info.plist` (Mencegah Hardcoding)**
1.  **GoogleClientID Entry:** Tambahkan entri kunci baru di Info.plist proyek:
    *   Key: `GoogleClientID`
    *   Value: `[GOOGLE_CLIENT_ID_DARI_GCP].apps.googleusercontent.com`
2.  **Custom URL Schemes (Redirect Callback):** Registrasikan skema URL kustom agar iOS dapat merutekan callback Google kembali ke aplikasi:
    ```xml
    <key>CFBundleURLTypes</key>
    <array>
        <dict>
            <key>CFBundleTypeRole</key>
            <string>Editor</string>
            <key>CFBundleURLSchemes</key>
            <array>
                <!-- Reversed Client ID format -->
                <string>com.googleusercontent.apps.[GOOGLE_CLIENT_ID_DARI_GCP]</string>
            </array>
        </dict>
    </array>
    ```

### **B. Pembaruan Kode `GoogleOAuthCoordinator`**
Modifikasi kode di `LoginView.swift` agar memuat Client ID secara dinamis dari `Info.plist` dan menggunakan Reversed Client ID sebagai skema callback URL:

```swift
final class GoogleOAuthCoordinator: NSObject, ASWebAuthenticationPresentationContextProviding {
    private var activeSession: ASWebAuthenticationSession?

    nonisolated func presentationAnchor(for session: ASWebAuthenticationSession) -> ASPresentationAnchor {
        MainActor.assumeIsolated {
            UIApplication.shared.connectedScenes
                .compactMap { $0 as? UIWindowScene }
                .flatMap { $0.windows }
                .first { $0.isKeyWindow } ?? UIWindow()
        }
    }

    func requestIDToken() async throws -> String {
        // 1. Ambil Google Client ID secara dinamis dari Info.plist
        guard let clientID = Bundle.main.object(forInfoDictionaryKey: "GoogleClientID") as? String, !clientID.isEmpty else {
            throw APIError.serverError(0, "GoogleClientID tidak terkonfigurasi di Info.plist")
        }
        
        // 2. Tentukan Reversed Client ID sebagai Skema URL Callback
        let components = clientID.components(separatedBy: ".")
        let reversedClientID = components.reversed().joined(separator: ".")
        let redirectURI = "\(reversedClientID):/oauth2callback"

        var comps = URLComponents(string: "https://accounts.google.com/o/oauth2/v2/auth")!
        comps.queryItems = [
            URLQueryItem(name: "client_id",     value: clientID),
            URLQueryItem(name: "redirect_uri",  value: redirectURI),
            URLQueryItem(name: "response_type", value: "id_token"),
            URLQueryItem(name: "scope",         value: "openid email profile"),
            URLQueryItem(name: "nonce",         value: UUID().uuidString),
        ]
        guard let authURL = comps.url else { throw APIError.invalidURL }

        return try await withCheckedThrowingContinuation { continuation in
            // Menggunakan reversedClientID sebagai skema callback yang diintersep oleh iOS
            let session = ASWebAuthenticationSession(
                url: authURL,
                callbackURLScheme: reversedClientID
            ) { callbackURL, error in
                if let error { 
                    continuation.resume(throwing: error)
                    return 
                }
                guard let fragment = callbackURL?.fragment,
                      let idToken = URLComponents(string: "?\(fragment)")?
                          .queryItems?.first(where: { $0.name == "id_token" })?.value
                else {
                    continuation.resume(throwing: APIError.serverError(0, "Token Google tidak ditemukan di URL fragment"))
                    return
                }
                continuation.resume(returning: idToken)
            }
            session.presentationContextProvider = self
            session.prefersEphemeralWebBrowserSession = true
            session.start()
            self.activeSession = session
        }
    }
}
```

## 6. Verification & Test Plan

### **A. Skenario Pengujian Unit & Integrasi**
1.  **GCP Config Verification (Smoke Test):**
    *   Memastikan nilai `GoogleClientID` berhasil terbaca dari `Info.plist` dan nilainya tidak kosong.
    *   Memastikan format `reversedClientID` tergenerasi dengan benar sesuai aturan Google (urutan domain dibalik).
2.  **ASWebAuthenticationSession Interception Test:**
    *   Mengetuk tombol login, memastikan lembar web terbuka dengan URL tujuan yang berisi parameter query `client_id` dan `redirect_uri` yang benar.
    *   Membatalkan login secara manual (menutup web view), memastikan error `canceledLogin` ditangani dengan anggun (tanpa memunculkan alert error yang mengganggu user).
3.  **Backend Verification Offline (Penting):**
    *   **Uji Positif:** Mengirimkan ID Token Google yang valid ke `/auth/google` -> Memastikan backend merespons dengan status 200 dan mengembalikan JWT Token aplikasi yang berlaku selama 30 hari.
    *   **Uji Negatif (Token Salah):** Mengirimkan token acak/palsu -> Memastikan backend merespons dengan status 401 Unauthorized.
    *   **Uji Negatif (Email Tidak Terdaftar):** Mengirimkan token Google yang valid namun emailnya tidak sama dengan `AUTHORIZED_OWNER_EMAIL` -> Memastikan backend merespons dengan status 403 Forbidden.
    *   **Uji Negatif (Masa Aktif Token Habis):** Mengirimkan ID Token Google yang valid namun sudah kadaluarsa (melewati klaim `exp`) -> Memastikan backend merespons dengan status 401 Unauthorized.
