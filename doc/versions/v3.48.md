# Version 3.48 - Integrasi Login Google SSO & Sistem Undangan Anggota (Invitation Code - Multi Admin)

## 1. Problem / Opportunity
*   **Context:** Sistem otentikasi di aplikasi iOS Oura Studio sebelumnya dibatasi hanya untuk satu pemilik tunggal (`AUTHORIZED_OWNER_EMAIL`). Pengembang tidak memiliki akun Apple Developer berbayar, sehingga metode *Universal Links* atau deep linking kustom yang aman tidak dapat digunakan secara reliabel tanpa hambatan sertifikat atau konfigurasi domain yang rumit.
*   **Objective:** Menyusun rencana arsitektur dan spesifikasi teknis untuk mengintegrasikan Google Single Sign-In (SSO) secara native dengan sistem multi-user berbasis **Kode Undangan (Invitation Code)** 6-digit serta mendukung **Daftar Email Admin Berkelompok (Multi-Admin)** pada file konfigurasi environment. Hal ini memungkinkan:
    1.  Admin berkelompok (`AUTHORIZED_OWNER_EMAIL` berisi daftar email yang dipisahkan koma) dapat masuk sebagai Admin utama secara langsung tanpa memerlukan undangan.
    2.  Admin mana pun dari kelompok tersebut dapat mengundang anggota baru tanpa memerlukan akun Apple Developer berbayar.
    3.  Anggota yang diundang dapat mendaftarkan diri secara mandiri dan aman menggunakan akun Google mereka setelah memvalidasi kode undangan 6-digit.
    4.  Pembedaan peran (*role*) yang jelas antara **Admin** (memiliki akses penuh dan hak mengundang) dan **Member** (memiliki akses operasional penuh ke semua API, tetapi tidak dapat mengundang orang lain).

## 2. User Flow & UX Specifications
*   **Entry Point:** Layar login (`LoginView`) yang muncul otomatis ketika `appState.isAuthenticated == false`.
*   **UI Components:**
    *   **"Masuk dengan Google" Button:** Tombol masuk utama menggunakan ikon Google bermerek.
    *   **"Punya Kode Undangan?" Button:** Tombol teks sekunder yang terletak di bawah tombol login utama untuk membuka lembar verifikasi kode undangan bagi pengguna baru.
    *   **Invitation Input Sheet:** Lembar geser (*sheet*) sederhana yang meminta:
        1.  *Email:* Alamat email penerima undangan.
        2.  *Kode Undangan:* Kolom teks 6-karakter dengan kapitalisasi otomatis (*autocapitalized*).
    *   **Loading State & Error Banner:** Animasi sirkuler `ProgressView` dan banner merah estetik di atas tombol login jika terjadi kegagalan sistem atau otentikasi ditolak (403/401).

*   **User Journey (Invitation & Registration):**
    1.  **Admin** memasukkan email calon anggota di tab pengelola pengguna (Lainnya), dan backend menghasilkan kode undangan 6-digit (misal: `8X2K9F`). Admin mengirimkan kode ini secara manual ke calon anggota.
    2.  **Calon Anggota** membuka aplikasi Oura Studio, mengetuk tombol **"Punya Kode Undangan?"** di layar login.
    3.  Calon Anggota memasukkan email dan kode undangan 6-digit, lalu mengetuk **"Verifikasi Kode"**.
    4.  Aplikasi mengirimkan request verifikasi ke backend (`POST /auth/verify-invite`).
    5.  Jika kode valid dan belum kedaluwarsa, backend merespons dengan `200 OK` berisi `invitation_token` sementara yang aman. Aplikasi menyimpan token verifikasi sementara ini di memori aplikasi (`AppState`).
    6.  Calon Anggota kemudian mengetuk tombol **"Masuk dengan Google"** menggunakan akun Google yang emailnya cocok dengan email penerima undangan.
    7.  Aplikasi memproses login native `ASWebAuthenticationSession` seperti biasa, mengekstrak `id_token` Google, lalu mengirimkannya ke backend (`POST /auth/google`) beserta `invitation_token` sementara yang tersimpan di memori.
    8.  Backend memvalidasi `id_token` Google dan memadankannya dengan `invitation_token`. Jika cocok, backend mendaftarkan akun baru tersebut ke tabel `owner_account` dengan peran `member`, menandai undangan sebagai telah digunakan, menerbitkan token JWT utama, dan pengguna masuk secara otomatis ke `MainTabView`.

## 3. Database Schema (FastAPI / SQLAlchemy)

Tabel otentikasi di PostgreSQL/Supabase diperluas untuk mendukung peran ganda (*role*) dan pencatatan kode undangan:

```sql
-- 1. Penambahan kolom 'role' pada tabel owner_account
ALTER TABLE owner_account ADD COLUMN role VARCHAR(20) NOT NULL DEFAULT 'member';

-- Catatan: Pengguna yang termasuk dalam daftar AUTHORIZED_OWNER_EMAIL default di-provision otomatis sebagai 'admin'.

-- 2. Pembuatan tabel baru 'invitation' untuk melacak kode undangan
CREATE TABLE invitation (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email       TEXT NOT NULL UNIQUE,          -- Email target yang diundang (satu undangan aktif per email)
    code        VARCHAR(6) NOT NULL UNIQUE,    -- 6-digit kode alfanumerik kapital acak (misal: '8X2K9F')
    role        VARCHAR(20) NOT NULL DEFAULT 'member',
    created_by  UUID REFERENCES owner_account(id),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at  TIMESTAMPTZ NOT NULL,          -- Berlaku selama 48 jam sejak pembuatan
    is_used     BOOLEAN NOT NULL DEFAULT false
);
```

## 4. API Contract (FastAPI)

### **A. POST /api/v1/invitations**
Endpoint khusus Admin untuk membuat kode undangan baru bagi email tertentu.
*   **Request Headers:** `Authorization: Bearer <JWT_ADMIN>`
*   **Request Body:**
    ```json
    {
      "email": "member@example.com",
      "role": "member"
    }
    ```
*   **Response (201 Created):**
    ```json
    {
      "email": "member@example.com",
      "code": "8X2K9F",
      "role": "member",
      "expires_at": "2026-09-06T15:00:00Z"
    }
    ```
*   **Error Responses:**
    *   `403 Forbidden` (Pengguna yang memanggil bukan berkedudukan Admin).
    *   `400 Bad Request` (Email sudah diundang dan undangannya masih aktif, atau format email salah).

### **B. POST /api/v1/auth/verify-invite**
Endpoint publik untuk memvalidasi kode undangan sebelum pengguna masuk dengan Google SSO.
*   **Request Body:**
    ```json
    {
      "email": "member@example.com",
      "code": "8X2K9F"
    }
    ```
*   **Response (200 OK):**
    ```json
    {
      "invitation_token": "temp_inv_token_ey..."
    }
    ```
*   **Error Responses:**
    *   `400 Bad Request` (Kode undangan kosong atau format tidak sesuai).
    *   `404 Not Found` (Kode undangan tidak terdaftar).
    *   `410 Gone` (Undangan sudah digunakan atau telah kedaluwarsa).

### **C. POST /api/v1/auth/google**
Endpoint publik yang diperluas untuk menerima parameter opsional `invitation_token` guna pendaftaran member baru.
*   **Request Body:**
    ```json
    {
      "id_token": "eyJhbGciOiJSUzI1NiIsImtpZCI6...",
      "invitation_token": "temp_inv_token_ey..."  -- Opsional untuk pendaftaran member baru
    }
    ```
*   **Response (200 OK):**
    ```json
    {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "expires_at": "2026-10-03T15:00:00Z"
    }
    ```
*   **Logika Verifikasi & Provisioning di Backend:**
    1.  Verifikasi JWT signature dari Google `id_token` secara offline (seperti pada v3.48 lama).
    2.  Dapatkan `email` dan `google_sub` dari klaim token Google.
    3.  **Skenario Admin (Multi-Admin Parsing):**
        *   Backend mem-parsing `AUTHORIZED_OWNER_EMAIL` dari environment menjadi sekumpulan (*set*) email berih/trimmed (misal: `{"admin1@gmail.com", "admin2@gmail.com"}`).
        *   Jika `email` Google cocok dengan salah satu email di dalam daftar Admin:
            *   Jika user dengan email ini belum terdaftar di `owner_account`, daftarkan otomatis sebagai `admin`.
            *   Jika sudah terdaftar, pastikan peran adalah `admin` (update jika diperlukan) dan `google_sub` cocok dengan yang ada di database.
    4.  **Skenario Member Baru (Memerlukan `invitation_token`):**
        *   Jika `email` Google tidak termasuk dalam daftar Admin:
            *   Pastikan `invitation_token` dikirimkan dalam body request.
            *   Dekode dan validasi tanda tangan `invitation_token` (JWT sementara yang diterbitkan oleh server kita saat verifikasi kode sukses).
            *   Pastikan email di dalam `invitation_token` cocok dengan email dari Google `id_token`.
            *   Periksa tabel `invitation` untuk mematikan kode undangan tersebut valid (`is_used = false` dan belum kedaluwarsa).
            *   Daftarkan pengguna baru di `owner_account` dengan `role = 'member'`, `google_sub`, dan `email`.
            *   Set `is_used = true` pada tabel `invitation`.
    5.  **Skenario Member Terdaftar (Tanpa `invitation_token`):**
        *   Jika email dari Google `id_token` sudah terdaftar di `owner_account`, pastikan `google_sub` cocok dengan sub yang terdaftar di database.
    6.  Terbitkan JWT aplikasi utama untuk pengguna yang bersangkutan.

## 5. Frontend & iOS Specifications (SwiftUI)

### **A. Lembar Verifikasi Kode Undangan (`LoginView.swift`)**
*   Menambahkan tombol sekunder **"Punya Kode Undangan?"** di bawah tombol login utama.
*   Membuka `sheet` berisi form untuk mengisi `email` and 6-digit `code`.
*   Menyediakan tombol verifikasi yang menjalankan pemanggilan API ke `POST /auth/verify-invite`.
*   Jika sukses, simpan `invitationToken` ke dalam `@State` atau `AppState` dan tampilkan alert sukses: *"Kode undangan terverifikasi! Silakan klik tombol 'Masuk dengan Google' menggunakan email Anda untuk menyelesaikan pendaftaran."*

### **B. Penambahan Parameter pada APIService & Model**
*   Membuat model data baru untuk request dan response verifikasi undangan:
    ```swift
    struct VerifyInviteRequest: Codable {
        let email: String
        let code: String
    }
    struct VerifyInviteResponse: Codable {
        let invitationToken: String
    }
    ```
*   Memperbarui struktur `GoogleLoginRequest` agar menyertakan parameter `invitationToken` opsional:
    ```swift
    struct GoogleLoginRequest: Codable {
        let idToken: String
        let invitationToken: String?
    }
    ```

## 6. Verification & Test Plan

### **Skenario Pengujian Unit & Integrasi**
1.  **Pembuatan Undangan (Admin Only):**
    *   Memastikan endpoint `POST /invitations` menolak akses jika dipanggil oleh non-admin (403 Forbidden).
    *   Memastikan kode 6-digit tergenerasi secara acak dan kapital.
2.  **Verifikasi Kode Undangan (Verify Invite):**
    *   Uji Positif: Email & kode yang valid mengembalikan token sementara.
    *   Uji Negatif: Kode salah format, salah isi, kedaluwarsa, atau sudah digunakan mengembalikan status error yang sesuai (400, 404, 410).
3.  **Registrasi Member Via Google SSO:**
    *   Uji Positif: Menandatangani registrasi dengan `id_token` Google yang valid + `invitation_token` yang valid mendaftarkan member baru di database dan mengubah status undangan menjadi `is_used = true`.
    *   Uji Negatif: Registrasi ditolak jika email Google tidak cocok dengan email di dalam `invitation_token`.
