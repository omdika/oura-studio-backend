## Latar Belakang

Tab **Produksi → Bahan → Detail Bahan** menampilkan section "Pergerakan Stok" yang seharusnya berisi dua jenis entri:
1. **Pembelian** (`MaterialPurchase[]`) — sudah tampil dari `GET /materials/{id}/purchases` ✅
2. **Pemakaian** (`MaterialUsageEntry[]`) — selalu kosong karena `getMaterialUsage` di iOS hardcode `return []` ❌

Root cause: endpoint `GET /materials/{id}/usage` tidak pernah diimplementasikan di backend.

Investigation hasil (2026-08-17):
- **Kain (fabric):** data pemakaian bisa diderivasi dari `cutting_layout` (status='used') → `cutting_layout_item` (fabric_length_used_cm) → `production_batch_layout` → `production_batch` (confirmed_at = tanggal pemakaian).
- **Hardware & Benang:** `_fifo_deduct_hardware()` hanya mutasi qty di `material_purchase.remaining_*`, tidak menulis log historis. Tidak ada data pemakaian yang bisa diderivasi.

**Keputusan:** build endpoint untuk kain dulu. Hardware/thread return `[]` sampai ada logging table yang didesain.

## Endpoint Spec

```
GET /materials/{material_id}/usage
Authorization: Bearer <jwt>
```

### Query params (opsional)
| Param | Type | Default | Keterangan |
|---|---|---|---|
| `from` | `date` (`yyyy-MM-dd`) | — | Filter pemakaian sejak tanggal ini |
| `to` | `date` (`yyyy-MM-dd`) | — | Filter pemakaian sampai tanggal ini |
| `limit` | `int` | 50 | Max jumlah entri |

### Response shape

```json
[
  {
    "id": "uuid",
    "material_id": "uuid",
    "deducted_cm": 150.0,
    "date": "2026-08-14",
    "description": "Batch #abc123 · M · Satin Pelangi",
    "product_size_id": "uuid",
    "product_sku": "SCRSAT",
    "size_label": "M"
  }
]
```

### Field mapping ke iOS `MaterialUsageEntry`

```swift
struct MaterialUsageEntry: Identifiable, Codable {
    var id: UUID
    var materialId: UUID          // "material_id"
    var deductedCm: Double        // "deducted_cm"
    var date: Date                // "date" — yyyy-MM-dd
    var description: String       // "description"
    var productSizeId: UUID?      // "product_size_id"
    var productSku: String?       // "product_sku"
    var sizeLabel: String?        // "size_label"
}
```

Catatan: `MaterialUsageEntry` di iOS saat ini adalah `Identifiable` tapi NOT `Codable` — frontend perlu update untuk decode response ini (terpisah dari backend task ini).

## Sumber Data (Kain)

```sql
SELECT
    cli.id                          AS id,
    mp.material_id                  AS material_id,
    cli.fabric_length_used_cm       AS deducted_cm,
    DATE(pb.confirmed_at)           AS date,
    -- description: singkat
    CONCAT('Batch · ', ps.size_label, ' · ', ps.fabric_variant_name) AS description,
    ps.id                           AS product_size_id,
    p.sku                           AS product_sku,
    ps.size_label                   AS size_label
FROM cutting_layout_item cli
JOIN cutting_layout cl ON cl.id = cli.cutting_layout_id
JOIN material_purchase mp ON mp.id = cl.material_purchase_id
JOIN production_batch_layout pbl ON pbl.cutting_layout_id = cl.id
JOIN production_batch pb ON pb.id = pbl.production_batch_id
JOIN product_size ps ON ps.id = cli.product_size_id
JOIN product p ON p.id = ps.product_id
WHERE
    mp.material_id = :material_id
    AND cl.status = 'used'
    AND pb.status = 'confirmed'
ORDER BY pb.confirmed_at DESC
```

**Filter hardware/thread:** jika `material.category != 'fabric'`, return `[]` langsung tanpa query.

---

## Edge Cases

- **Material belum pernah dipakai di batch confirmed:** return `[]` — bukan error.
- **cutting_layout belum di-confirm (status='suggested'):** dikecualikan oleh `cl.status = 'used'` + `pb.status = 'confirmed'`.
- **Batch multi-fabric (banyak cutting layout per batch):** tiap `cutting_layout_item` adalah satu entri terpisah — ini benar, karena setiap row merepresentasikan pemakaian dari satu roll kain tertentu.
- **`product_size.fabric_variant_name` null:** description fallback ke hanya `size_label`.
- **`pb.confirmed_at` null** (batch lama sebelum v2.12 migration): gunakan `pb.produced_at` sebagai fallback, atau skip entri tersebut (flagged, bukan crash).
