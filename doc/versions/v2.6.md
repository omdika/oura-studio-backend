# v2.6 — Two Contract Bugs Fixed (2026-08-08)
**Date:** 2026-08-08  
**Changed by:** Backend (reported by Frontend)  
**Status:** ✅ IMPLEMENTED

---

## Summary

Dua bug di API contract yang dilaporkan Frontend saat integrasi live, keduanya sudah diperbaiki.

---

## Fix 1 — GET /reports/dashboard: tambah today_units_sold

**Before:** response tidak menyertakan `today_units_sold`.

**After:**
```json
{
  "today_revenue": 0.0,
  "today_order_count": 0,
  "today_units_sold": 0,
  "today_profit": 0.0,
  "low_stock_alerts": [...]
}
```

`today_units_sold` = `SUM(qty)` dari semua `sales_order_item` di mana `sales_order.sold_at` hari ini (server timezone), non-cancelled orders only. Default 0.

---

## Fix 2 — PATCH /production-batches/{id}/items/{item_id}: response harus item, bukan batch

**Before:** endpoint mengembalikan seluruh objek `production_batch` (root `id` = batch ID).

**After:** kembalikan hanya item yang di-update:

```json
{
  "id": "<item_id>",
  "production_batch_id": "<batch_id>",
  "product_size_id": "<uuid>",
  "pattern_spec_id": "<uuid>",
  "qty_actual": 5,
  "qty_suggested": 10,
  "fabric_cost_per_piece": 2380.0,
  "hpp_fabric": 0.0,
  "hpp_pooled_material": 0.0,
  "hpp_hardware": 0.0,
  "hpp_labor": 0.0,
  "hpp_overhead": 0.0,
  "hpp_total": 0.0
}
```

`hpp_*` fields boleh `0.0` untuk draft batch — HPP baru dihitung saat `POST /confirm`.
`qty_suggested` adalah dari `cutting_layout_item`; null untuk manually-entered items.
`product_size_id` / `pattern_spec_id` nullable.

---

## Note: product_size_id di GET /production-batches

Dilaporkan juga bahwa `product_size_id` hilang untuk confirmed batch items. Setelah investigasi backend, field ini sudah always non-null (enforced di schema). iOS client sudah menggunakan workaround tolerant decode (`UUID?`) — tidak perlu perubahan backend.
