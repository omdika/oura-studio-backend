# Version 3.58 - Intercept Harga Event (Temporary Price Adjustment)

## 1. Problem / Opportunity
*   **Context:** Saat ini, harga jual produk bersifat statis dan langsung diambil dari data produk. Untuk event atau promosi tertentu, seringkali diperlukan penyesuaian harga jual (misalnya, menaikkan harga sebesar X rupiah untuk semua produk) secara sementara tanpa mengubah harga dasar produk secara permanen.
*   **Objective:** Mengimplementasikan fungsionalitas yang memungkinkan penyesuaian harga jual produk secara global dan sementara untuk event tertentu melalui pengaturan, yang akan otomatis mempengaruhi harga yang ditampilkan di daftar produk dan harga yang tersimpan saat pencatatan penjualan.

## 2. User Flow & UX Specifications
*   **Entry Point:** Pengguna mengakses fitur ini melalui menu "Pengaturan" (Settings), di mana akan ada pilihan baru bernama "Intercept / Ubah Harga Event".
*   **UI Components:**
    *   **EventPriceAdjustmentView (New View):**
        *   Sebuah `Toggle` dengan label "Aktifkan Penyesuaian Harga Event" untuk mengaktifkan/menonaktifkan fitur ini.
        *   Sebuah `CurrencyInputField` yang hanya aktif jika toggle di atas ON, untuk menginput "Jumlah Penyesuaian Harga (Rp)". Nilai default 0.
        *   Tombol "Simpan Pengaturan".
    *   Ketika fitur aktif, di `ProdukListView` dan `ProdukDetailView`, harga yang ditampilkan adalah harga dasar `product.price` + `adjustment_amount`.
    *   Ketika mencatat penjualan, harga yang tersimpan di `SalesItem` adalah harga dasar `product.price` + `adjustment_amount` (jika aktif).
*   **Validation Rules (`canSave`):**
    *   Jumlah penyesuaian harga harus berupa angka positif atau nol (>= 0).
*   **State & Progressive Disclosure:** `CurrencyInputField` untuk jumlah penyesuaian harga akan `disabled` jika toggle "Aktifkan Penyesuaian Harga Event" dalam posisi OFF.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** `settings` (modifikasi/penambahan entri)
*   **New / Modified Columns:**
    *   Tidak ada penambahan kolom. Kebutuhan akan disimpan sebagai key-value pair di tabel `settings`.
    *   Dua entri baru di tabel `settings`:
        *   `key='event_price_adjustment_active'`, `value='true'` atau `'false'` (tipe string/boolean)
        *   `key='event_price_adjustment_amount'`, `value='10000'` (tipe string, disimpan sebagai integer di backend)

## 4. API Contract (FastAPI)
*   **Endpoints:**
    *   `GET /api/v1/settings`
        *   **Response Body:** Mengembalikan semua pengaturan yang relevan, termasuk `event_price_adjustment_active` dan `event_price_adjustment_amount`.
    *   `POST /api/v1/settings/update`
        *   **Request Body:** `{'key': 'event_price_adjustment_active', 'value': 'true'}` atau `{'key': 'event_price_adjustment_amount', 'value': '10000'}`
        *   **Validation:** Validasi untuk `adjustment_amount` harus `>= 0`.
    *   **Modifikasi Endpoint Existing:**
        *   `GET /api/v1/products` (dan endpoint yang relevan seperti `GET /api/v1/products/{product_id}`):
            *   Backend akan mengambil `event_price_adjustment_active` dan `event_price_adjustment_amount` dari tabel `settings`.
            *   Jika `active` adalah `true`, harga setiap produk yang dikembalikan di response body akan ditambahkan dengan `adjustment_amount` sebelum dikirim ke frontend. Frontend hanya menerima harga final.
        *   `POST /api/v1/sales` (dan endpoint terkait pencatatan penjualan):
            *   Saat menerima input penjualan, backend akan secara internal menghitung harga jual produk berdasarkan harga dasar produk + `adjustment_amount` (jika aktif).
            *   Harga ini yang akan disimpan ke `sales_items.selling_price`.

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:**
    *   Model untuk `Setting` (key, value).
    *   `APIService` akan memiliki method baru untuk `fetchSettings()` dan `updateSetting(key: String, value: String)`.
    *   `Product` model tidak perlu diubah, karena harga yang diterima dari API sudah disesuaikan.
*   **Views & Controllers:**
    *   `SettingsView`: Menambahkan `NavigationLink` ke `EventPriceAdjustmentView`.
    *   `EventPriceAdjustmentView.swift` (New File): Implementasi tampilan dan logika untuk mengatur penyesuaian harga event.
    *   `ProdukListView.swift`: Menggunakan harga yang diterima dari API (sudah disesuaikan).
    *   `ProdukDetailView.swift`: Menggunakan harga yang diterima dari API (sudah disesuaikan).
    *   `PenjualanEntryView.swift`: Pastikan harga yang dipilih/ditampilkan adalah harga yang dari API (sudah disesuaikan) saat menambahkan item penjualan.

## 6. Verification & Test Plan
*   **Smoke Test:**
    *   Verify `EventPriceAdjustmentView` can be accessed from `SettingsView`.
    *   Verify toggling and inputting amount doesn't crash the app.
*   **Sanity Test Scenarios:**
    1.  **Aktifkan Penyesuaian:** Atur `adjustment_amount` ke 10.000, aktifkan. Verifikasi harga di `ProdukListView` bertambah 10.000. Catat penjualan, verifikasi harga yang tersimpan di `SalesDetailView` dan database adalah harga + 10.000.
    2.  **Nonaktifkan Penyesuaian:** Nonaktifkan penyesuaian. Verifikasi harga di `ProdukListView` kembali ke harga dasar. Catat penjualan, verifikasi harga yang tersimpan adalah harga dasar.
    3.  **Jumlah Nol:** Atur `adjustment_amount` ke 0, aktifkan. Verifikasi harga tidak berubah.
    4.  **Backend Logic:** Pastikan validasi di backend untuk `adjustment_amount` (>= 0) berfungsi.
