# Version 3.63 - Migrasi Deploy ke FastAPI Cloud + Image Baru ke Supabase Storage (Opsi A)

## 1. Problem / Opportunity
*   **Context:** Backend FastAPI saat ini jalan di Cloud Run (Dockerfile `python:3.11-slim`, `uvicorn app.main:app --port $PORT`) dengan DB Supabase Postgres (via `SUPABASE_DB_URL` pooler) dan upload foto produk ke GCS bucket (`settings.gcs_bucket_name = "oura-studio-prod-bucket"`, helper `_upload_jpeg_to_gcs` di `app/routers/products.py:120`, dep `google-cloud-storage==2.18.2`). Owner mau pindah hosting ke FastAPI Cloud managed (`fastapicloud.com`), DB tetap Supabase, image baru ditulis ke Supabase Storage bucket public.
*   **Objective:** Backend bisa di-deploy via `fastapi deploy` (tanpa Dockerfile) ke FastAPI Cloud, tetap konek ke Supabase Postgres yang sama (tanpa migrasi data), upload/galeri produk baru tersimpan di Supabase Storage, URL GCS lama tetap bisa dibaca (tidak ada rewrite URL / migrasi file fisik), kontrak API tidak berubah, iOS tanpa perubahan kode.

## 2. Deploy Flow & Env Specifications (tidak ada perubahan UX / UI)
*   **Entry Point:** Dari root `backend/`, jalankan `fastapi deploy`. Entrypoint eksplisit `app.main:app` (objek `app` sudah ada di `app/main.py`, tidak perlu rename).
*   **Verifikasi lokal (wajib sebelum deploy):** `fastapi dev` harus jalan tanpa argumen path setelah `pyproject.toml` ditambah.
*   **Zero-downtime note:** FastAPI Cloud rollout gradual (old + new instance bisa hidup bersamaan). Tidak ada migration DB di versi ini, jadi aman. Cloud Run lama dibiarkan hidup sampai cutover + smoke test lolos.
*   **Environment variables (set via `fastapi cloud env set --secret <KEY> "<val>"`, atau dashboard → Environment Variables):**
    *   `SUPABASE_DB_URL` — WAJIB pooler variant (`...pooler.supabase.com:5432/postgres`), JANGAN direct `db.<ref>.supabase.co` (IPv6-only, gagal resolve). Alternatif native: integrasi Supabase dashboard yang inject `DATABASE_URL` — didukung via fallback di `config.py` (lihat §5.4).
    *   `SUPABASE_URL` — e.g. `https://<ref>.supabase.co` (dipakai bangun public URL + Storage REST).
    *   `SUPABASE_SERVICE_ROLE_KEY` — secret, dipakai upload/delete Storage server-side (bypass RLS).
    *   `SUPABASE_STORAGE_BUCKET` — default `product-images` (public-read).
    *   `JWT_SECRET`, `JWT_ALGORITHM` (default HS256), `JWT_EXPIRE_MINUTES`, `AUTHORIZED_OWNER_EMAIL`, `GOOGLE_CLIENT_ID` — sama seperti `.env` sekarang.
*   **Supabase dashboard (manual, sekali saja, sebelum deploy):** Storage → New bucket → nama `product-images` → **Public bucket ON**. Policies default public-read cukup karena upload memakai service_role (bypass RLS). Tidak perlu signed URL.
*   **Validation Rules (`canSave` analog — deploy gate):**
    *   `fastapi dev` lokal lolos tanpa path arg.
    *   `alembic upgrade head` sudah dijalankan manual ke Supabase DB SEBELUM deploy (tidak ada migration baru di v3.63, tapi gate ini wajib untuk versi berikutnya).
    *   Semua env `--secret` di atas ter-set di FastAPI Cloud sebelum deploy pertama.
*   **State & Progressive Disclosure:** N/A (infra).

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** NONE. Tidak ada kolom/tabel/index baru. Tidak ada file migrasi Alembic baru.

Untuk rilis berikutnya yang membawa migration, ikuti aturan FastAPI Cloud: migration ADD-column jalan SEBELUM deploy kode; migration DROP-column jalan SETELAH kode baru yang tidak lagi memakai kolom itu sudah live.

## 4. API Contract (FastAPI)
*   **Endpoints:** TIDAK ADA endpoint baru / hapus / ubah signature. Semua route produk/galeri (`POST /products/{sku}/images`, `POST /products/{sku}/sizes/{size_id}/images/*`, `DELETE ...`, `GET .../shopee-payload`) request/response shape IDENTIK.
*   **Satu-satunya perbedaan observable:** nilai `image_url` untuk upload BARU berubah origin-nya dari `https://storage.googleapis.com/<gcs-bucket>/...` menjadi `https://<ref>.supabase.co/storage/v1/object/public/product-images/...`. iOS memperlakukan `image_url` sebagai opaque string → tidak perlu perubahan.
*   **Backward compat:** URL GCS lama yang tersimpan di `product_image.image_url` / `product_size_image.image_url` tetap di-serve apa adanya (read path tidak di-rewrite). Delete endpoint: kalau `image_url` masih origin GCS → hapus DB row saja, skip delete objek GCS (best-effort, log print, JANGAN 500). Kalau origin Supabase → delete objek via Storage REST best-effort.
*   **Validation & Errors:** Tidak berubah (JPEG-only check, 404 product/size/image, 409 cover constraint tetap).

*   **5.5 `app/routers/products.py` (EDIT — satu-satunya perubahan logic):**
    *   Ganti `_upload_jpeg_to_gcs(blob_name, file_bytes) -> str` dengan `_upload_jpeg_to_storage(blob_name, file_bytes) -> str` memakai `httpx` (sudah ada di requirements `httpx==0.27.2`, JANGAN tambah `supabase-py` / `storage3` — hindari dep baru):
    ```python
    def _upload_jpeg_to_storage(blob_name: str, file_bytes: bytes) -> str:
        """Upload JPEG bytes to Supabase Storage, return public URL."""
        from app.config import settings
        import httpx
        base = settings.supabase_url.rstrip("/")
        bucket = settings.supabase_storage_bucket.strip().strip("/")
        key = settings.supabase_service_role_key
        url = f"{base}/storage/v1/object/{bucket}/{blob_name}"
        headers = {"apikey": key, "Authorization": f"Bearer {key}", "Content-Type": "image/jpeg"}
        try:
            r = httpx.post(url, content=file_bytes, headers=headers, timeout=30)
            r.raise_for_status()
        except Exception as e:
            print(f"Supabase Storage upload failed: {e}.")
            raise
        return f"{base}/storage/v1/object/public/{bucket}/{blob_name}"
    ```
    *   Rename semua call site (`upload_product_image` ~line 581 + upload size-image paths) ke helper baru. Blob path TIDAK berubah (`products/{sku}/gallery/{uuid}.jpg` dst.) agar prefix konsisten.

Kalau URL GCS lama (`storage.googleapis.com/...`) → skip (DB row tetap dihapus, return tanpa error). Hapus pemakaian `google.cloud.storage` di file ini.

## 6. Verification & Test Plan
*   **Smoke Test:**
    1. `fastapi dev` lokal tanpa path arg → `GET /health` 200, `GET /docs` 200.
    2. `fastapi deploy` sukses → URL `*.fastapicloud.dev` live → `GET /health` 200 tanpa auth.
    3. Auth: `POST /api/v1/auth/google` dengan ID token valid → 200 + JWT; endpoint tanpa Bearer → 401.
*   **Sanity Test Scenarios (wajib, pakai data real):**
    1. **Upload galeri baru → Supabase:** `POST /products/{sku}/images` (JPEG < 1.8MB) → 201, `image_url` diawali `https://<ref>.supabase.co/storage/v1/object/public/product-images/products/...`; buka URL di browser → image tampil public tanpa auth; row `product_image` tersimpan.
    2. **URL lama tetap jalan:** `GET /products/{sku}/images` masih kembalikan row lama ber-origin `storage.googleapis.com/...`; `GET .../shopee-payload` kolom gambar tetap terisi campuran GCS+Supabase tanpa error.
    3. **Delete baru:** `DELETE /products/{sku}/images/{id}` untuk URL Supabase → 204, objek hilang dari bucket (GET URL → 400/404), row hilang; untuk URL GCS lama → 204, row hilang, tidak 500 walau objek GCS tidak disentuh.
    4. **HPP/report tidak regresi:** `GET /products/{sku}/sizes` (cek `latest_hpp_breakdown`), `GET /reports/dashboard`, `GET /reports/sales?from=...&to=...` sama seperti sebelum migrasi (bandingkan dengan Cloud Run lama).
    5. **Alembic no-op:** `alembic upgrade head` → `already up to date`, tidak ada migration pending.
*   **Rollback:** Jika smoke/sanity gagal → arahkan iOS kembali ke URL Cloud Run lama (jangan hapus service Cloud Run sampai 7 hari pasca-cutover). `git` rollback = checkout `main` (branch ini `chore/migrate-fastapicloud-supabase-storage` belum merge).
*   **Cutover checklist:** bucket `product-images` public dibuat → env secrets ter-set → deploy → smoke → sanity 1-5 → update base URL iOS → monitor logs/metrics 24 jam → (opsional) custom domain.
