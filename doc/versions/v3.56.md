# Version 3.55 - Perbaikan Performa Load Data Produk

## 1. Problem / Opportunity
*   **Context:** Pengguna mengalami waktu loading yang lama (sekitar beberapa detik) saat membuka daftar produk utama (`ProdukListView`), meskipun hanya ada sekitar 67 produk dan tanpa filter aktif. Investigasi awal menunjukkan bahwa API call untuk `getProducts()` dan `getAllProductSizes()` di `APIService` mungkin menjadi bottleneck utama, baik dari sisi performa backend maupun ukuran payload data.
*   **Objective:** Meningkatkan kecepatan loading daftar produk utama menjadi kurang dari 1 detik untuk 100-200 produk, serta membangun fondasi agar performa tetap baik seiring bertambahnya jumlah produk.

## 2. User Flow & UX Specifications
*   **Entry Point:** `ProdukListView` (saat pertama kali dibuka atau refresh).
*   **UI Components:**
    *   `ProdukListView` akan memuat data secara paginasi (lazy loading) jika jumlah produk melebihi `pageSize` tertentu (misalnya 20 atau 50).
    *   Indikator loading (misalnya `ProgressView` di bagian bawah daftar) akan ditampilkan saat data halaman berikutnya sedang dimuat.
*   **Validation Rules (`canSave`):** N/A (tidak ada perubahan UI input).
*   **State & Progressive Disclosure:** `ProdukListView` akan mengelola state `currentPage`, `isLoadingMore`, `hasMorePages` untuk pagination.

## 3. Database Schema Changes (FastAPI / SQLAlchemy)
*   **Affected Tables:** `products`, `product_sizes`.
*   **New / Modified Columns:** Tidak ada perubahan skema database secara langsung. Namun, indeks baru pada kolom yang sering di-query mungkin diperlukan di sisi backend untuk endpoint pagination (misalnya, `created_at` atau `id` untuk ordering).

## 4. API Contract (FastAPI)
*   **Endpoints:**
    *   **`GET /products`:**
        *   **Parameter Baru:**
            *   `page: int = Query(1, description="Nomor halaman untuk pagination")`
            *   `limit: int = Query(20, description="Jumlah item per halaman")`
        *   **Response Body (Modifikasi):**
            ```json
            {
                "data": [
                    {
                        "id": "uuid",
                        "name": "string",
                        "sku": "string",
                        "category": "string",
                        "is_archived": "boolean"
                        // ... bidang lain yang relevan untuk daftar
                    }
                ],
                "total_items": 123,
                "total_pages": 7,
                "current_page": 1,
                "next_page": 2,
                "prev_page": null
            }
            ```
    *   **`GET /product-sizes`:**
        *   **Parameter Baru:**
            *   `page: int = Query(1, description="Nomor halaman untuk pagination")`
            *   `limit: int = Query(50, description="Jumlah item per halaman")`
            *   `product_id: Optional[UUID] = Query(None, description="Filter ukuran berdasarkan ID produk")` (opsional, untuk optimasi lebih lanjut jika diperlukan)
        *   **Response Body (Modifikasi):** Struktur respons akan sama seperti `/products` (menggunakan `data`, `total_items`, `total_pages`, dsb.).

## 5. Frontend Changes (SwiftUI)
*   **Codable Models & APIService:**
    *   Membuat struktur `PaginatedResponse<T: Decodable>` untuk menangani format respons pagination baru.
    *   Memodifikasi `APIService.getProducts()` dan `APIService.getAllProductSizes()` untuk menerima parameter `page` dan `limit`, dan mengembalikan `PaginatedResponse<Product>` dan `PaginatedResponse<ProductSizeDetail>`.
*   **Views & Controllers:**
    *   **`ProdukListView.swift`:**
        *   Menambahkan `@State` untuk `currentPage`, `isLoadingMore`, `hasMorePages`.
        *   Mengimplementasikan logika pemuatan data halaman pertama di `.task { await loadFirstPage() }`.
        *   Mengimplementasikan logika pemuatan halaman berikutnya saat scroll mencapai akhir daftar (di `.onAppear` dari item terakhir) melalui fungsi `loadMoreProducts()`.
        *   Memperbarui `load()` menjadi `loadFirstPage()` dan `loadMoreProducts()` yang akan menggunakan parameter `page` dan `limit` ke `APIService`.
        *   Logika `refreshable` akan mereset ke halaman 1 dan memuat ulang.
        *   Pertimbangkan untuk mengoptimalkan `ProductGroupRow` jika profiling UI menunjukkan bottleneck.

## 6. Verification & Test Plan
*   **Smoke Test:**
    *   Aplikasi berhasil compile.
    *   Navigasi ke `ProdukListView` berhasil tanpa crash.
    *   Daftar produk awal ditampilkan.
*   **Sanity Test Scenarios:**
    *   Memuat halaman pertama produk (misalnya 20 item) dengan cepat.
    *   Melakukan scroll ke bawah memicu pemuatan halaman berikutnya, dan item baru ditambahkan ke daftar.
    *   Mencapai akhir daftar, tidak ada lagi pemuatan data baru jika `hasMorePages` adalah `false`.
    *   Fungsi pull-to-refresh bekerja dengan benar, mereset daftar ke halaman pertama.
    *   Pencarian dan filter (jika diaktifkan) berfungsi dengan data yang sudah dimuat (atau di-reset dan dimuat ulang dengan parameter pencarian/filter).
