# v2.10 — Sizes List: Full Field Spec Implemented (2026-08-08)
**Date:** 2026-08-08  
**Changed by:** Backend  
**Status:** ✅ IMPLEMENTED

---

## Summary

Implementasi penuh spec dari v2.9 untuk `GET /products/{sku}/sizes`.

---

## Changes

### 1. production_stock_qty + manual_stock_qty

Ditambahkan ke `ProductSizeOut` (base schema yang dipakai list, by-ID, PATCH, dan POST responses):

```python
production_stock_qty: int  # SUM(change_qty) WHERE reason='production'
manual_stock_qty: int      # SUM(change_qty) WHERE reason IN ('initial', 'adjustment')
```

Computed dari `stock_ledger` table, fallback 0 jika tidak ada rows.

### 2. latest_hpp_breakdown key rename

`HppBreakdownOut` fields diganti dari nama kolom DB ke nama yang dispec:

| DB column         | Response key      |
|---|---|
| `hpp_fabric`      | `fabric`          |
| `hpp_pooled_material` | `pooled_material` |
| `hpp_hardware`    | `hardware`        |
| `hpp_labor`       | `labor`           |
| `hpp_overhead`    | `overhead`        |
| `hpp_total`       | `total`           |

Ini response-shape-only rename — field DB `production_batch_item.hpp_*` tidak berubah.

### 3. selling_price + current_stock_qty explicit

Sudah ada sejak v2.8 via `ProductSizeDetailOut`, dikonfirmasi explicit di `ProductSizeOut` base schema.

---

## Scope Tidak Berubah

- `POST /production-batches/{id}/confirm` dan endpoint lain yang menggunakan `production_batch_item.hpp_*` field names secara internal: tidak terpengaruh oleh rename di atas (rename hanya di response serializer `HppBreakdownOut`)
