# v2.5 — Hardware Purchase: Field `length_cm` Opsional (Backend Action Required)
**Date:** 2026-08-07  
**Changed by:** Frontend (spec update)

---

## Summary

Spec change: hardware materials kini bisa punya `qty` AND `length_cm`. Tidak ada migrasi DDL — kolom sudah ada di `material_purchase`. Yang berubah adalah backend logic di POST/PATCH endpoints.

---

## Backend Changes Required

### 1. POST /materials/{id}/purchases

**Tambahkan logic untuk hardware:**

```python
# Setelah validasi kategori
if material.category == 'hardware' and purchase.length_cm is not None:
    # Length-tracked hardware (e.g., elastic band, ribbon)
    if purchase.qty is None or purchase.qty <= 0:
        raise HTTPException(400, "qty wajib diisi untuk hardware dengan panjang")
    purchase.remaining_length_cm = purchase.qty * purchase.length_cm
elif material.category == 'fabric':
    # Existing behavior
    if not (purchase.width_cm and purchase.length_cm):
        raise HTTPException(400, "width_cm dan length_cm wajib untuk kain")
    purchase.remaining_length_cm = purchase.length_cm
else:
    # Thread, packaging, count-only hardware
    purchase.remaining_length_cm = None
```

### 2. PATCH /materials/{id}/purchases/{purchase_id}

**Tambahkan hardware ke blok "touched/consumed" check:**

```python
# Existing logic:
if material.category == 'fabric':
    is_touched = purchase.remaining_length_cm < original_length_cm

# Tambahkan:
elif material.category == 'hardware' and purchase.length_cm is not None:
    total_length = purchase.qty * purchase.length_cm
    is_touched = (purchase.remaining_length_cm is not None 
                  and purchase.remaining_length_cm < total_length)

if is_touched:
    # Reject qty / length_cm changes
    if any([body.qty, body.length_cm, body.width_cm]):
        raise HTTPException(400, "Tidak bisa mengubah dimensi purchase yang sudah dikonsumsi")
```

### 3. Consumption endpoint (hardware with length_cm)

Saat PatternSpec component dikonsumsi dalam produksi untuk hardware dengan `remaining_length_cm`:
- Kurangi `remaining_length_cm` sebesar `component.qty_per_unit × length_per_unit_cm × batch_qty`
- Jika `remaining_length_cm < 0`, handle gracefully (log warning, clamp to 0)

## Cost Calculation

Untuk hardware dengan `length_cm`:
```
cost_per_cm = total_cost / (qty × length_cm)
current_avg_cost = weighted average dari semua purchases, per cm
```

Untuk hardware tanpa `length_cm` (behavior lama):
```
cost_per_unit = total_cost / qty
current_avg_cost = weighted average per pcs
```

**Catatan:** kedua tipe bisa ada untuk material yang sama jika owner pernah beli dengan cara berbeda. Backend harus handle mixed history — gunakan satuan yang sesuai per purchase untuk weighted average.

## No Schema Migration Needed

Kolom `length_cm`, `qty`, dan `remaining_length_cm` sudah ada di `material_purchase`. Tidak perlu `ALTER TABLE`.
