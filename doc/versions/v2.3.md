## 1. Picker Sheet Layout Fix (iOS 26 Liquid Glass)

**Bug:** `SearchableDropdownField` and `TokenizedMultiSelectField` presented their content via `fullScreenCover`. On iOS 26 with Liquid Glass enabled, this caused sheet content to anchor at the center or bottom of the screen instead of the top — making list items unreachable.

**Root cause:** iOS 26 Liquid Glass changes how `fullScreenCover` positions its content. `ZStack(alignment: .top)` and `VStack.frame(maxHeight: .infinity, alignment: .top)` both failed to override this behavior.

**Fix:** Wrap the sheet body in `NavigationStack`. The navigation bar naturally anchors content below it (to the top of the visible area). Both components now use:

```swift
NavigationStack {
    VStack(spacing: 0) {
        // search bar HStack
        Divider()
        ScrollView { /* item list */ }
        Spacer(minLength: 0)
    }
    .background(OuraTheme.Colors.background)
    .navigationTitle(label)
    .navigationBarTitleDisplayMode(.inline)
    .toolbar {
        ToolbarItem(placement: .cancellationAction) {
            Button("Batal") { isExpanded = false }
        }
    }
}
```

**Files:** `Components/SearchableDropdownField.swift`, `Components/TokenizedMultiSelectField.swift`

**Test:** Open any `SearchableDropdownField` or `TokenizedMultiSelectField` → sheet must show title in nav bar and list items immediately below it, not at screen center.

## 2. Keyboard "Done" Toolbar Removed

**Bug:** `NumericInputField` and `InlineSearchDropdownField` had a `ToolbarItemGroup(placement: .keyboard)` with a "Done" button. This added an extra tap to dismiss the keyboard, which is unnecessary — users can dismiss by tapping outside the field.

**Fix:** Removed the `.toolbar { ToolbarItemGroup(placement: .keyboard) { ... } }` block from both components. `@FocusState` and `.focused($...)` were retained for border highlight.

**Files:** `Components/NumericInputField.swift`, `Components/InlineSearchDropdownField.swift`

## 3. InlineSearchDropdownField Immediate List + "Tambah Baru"

**Changes:**
1. **List now visible immediately on focus** — previously gated behind `isEditing` state that required user to start typing. Changed condition to `if !filtered.isEmpty || onCreateNew != nil`.
2. **"Tambah Baru" always visible** when `onCreateNew != nil`:
   - Empty query → shows "Tambah Baru"
   - Non-empty query, no exact match → shows "Tambah '\<query\>'"
   - Non-empty query, exact match exists → hidden

**File:** `Components/InlineSearchDropdownField.swift`

**Test:** Navigate to Supplier field in TambahPembelianSheet or any view using `InlineSearchDropdownField` with `onCreateNew` set. Tap the field without typing — list of existing items and "Tambah Baru" button must appear immediately.

## 4. ReportsView — DateRangeField Component

**Redesign:** Replaced two `OuraDatePickerField` pickers + "Muat Laporan" button in `SalesReportDetailView` and `WasteReportView` with a single `DateRangeField` component.

### DateRangeField (private struct)

- Single tappable button styled like a form field
- Shows range label: "5 Agu – 5 Agu 2026" (Indonesian locale, short month for start, long for end)
- Presents `DateRangePickerSheet` on tap
- Accepts `onApply: () -> Void` callback — fired immediately after the sheet dismisses with new dates

### DateRangePickerSheet (private struct)

- `.presentationDetents([.medium])` sheet with drag indicator
- **Preset chips** (horizontal scroll): 7 Hari, 30 Hari, Bulan Ini, Bulan Lalu, 3 Bulan
- **Two DatePicker rows** (Dari / Sampai) using `.compact` display mode with tint `OuraTheme.Colors.accent`
  - "Dari" date capped at current "Sampai" value (prevents from > to)
  - "Sampai" date floored at current "Dari" value
- **"Terapkan" button** (`.confirmationAction` toolbar): calls `onApply(from, to)` then dismisses
- **"Batal" button** (`.cancellationAction` toolbar): dismisses without triggering callback

**File:** `Screens/Lainnya/ReportsView.swift`

## 5. Sales Report Date Filtering + Seed Data

**Bug:** `MockAPIService.getSalesReport(from:to:groupBy:)` was ignoring the `from`/`to` parameters and returning randomly generated chart data on every call, making it impossible to verify that date range changes actually filtered the data.

**Fix:**
- Rewrote `getSalesReport` to filter `_salesOrders` by `order.soldAt` date using `Calendar.startOfDay` comparisons
- Added `seedSalesOrders() -> [SalesOrder]` function creating 17 realistic seed orders:
  - Spread from 0 to 30 days ago
  - Use known product size IDs (M·Satin, M·Waffle, L·Satin, L·Waffle, L·Silk)
  - Realistic quantities (1–3 pcs) and prices (Rp 20.000–26.000)
  - Mix of paid and unpaid statuses
- `_salesOrders` initialized from `seedSalesOrders()` instead of `[]`

**File:** `Networking/MockAPIService.swift`

**Test:** In Laporan Penjualan, select "7 Hari" preset → chart should show only recent orders. Select "3 Bulan" → chart should show more data points spanning 30 days.

## 6. Backend Stack: PostgreSQL → Supabase

**Change:** Database stack updated from self-managed PostgreSQL to Supabase (PostgreSQL-compatible managed BaaS).

**Impact:**
- SQL schema in Section 3 of handoff is unchanged — Supabase uses PostgreSQL, all types and constraints are supported as-is
- FastAPI backend: use `asyncpg`/`psycopg2` with `SUPABASE_DB_URL` connection string, or `supabase-py` client library
- Replace `DATABASE_URL` env var with `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`
- Supabase auth/storage not used (app uses its own JWT auth)

**No iOS client changes required** — the frontend calls the FastAPI backend, not Supabase directly.
