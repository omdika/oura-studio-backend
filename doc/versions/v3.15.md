## Schema Migration

```sql
-- File: alembic/versions/XXXX_add_fabric_family_to_material.py
-- Atau jalankan langsung di Supabase SQL editor

ALTER TABLE material
    ADD COLUMN fabric_family VARCHAR(100) NULL;

-- Optional: index untuk GET /materials/families query
CREATE INDEX idx_material_fabric_family
    ON material(owner_id, fabric_family)
    WHERE fabric_family IS NOT NULL;
```

Tidak ada tabel baru. Tidak ada foreign key. Kolom nullable → tidak perlu default value → tidak ada data migration. Deployment: aman dijalankan saat server live (ALTER ADD COLUMN pada tabel PostgreSQL = lock singkat, tidak blocking pada Supabase).

## Pydantic Schema Changes

### `schemas/material.py`

```python
class MaterialBase(BaseModel):
    name: str
    category: str
    cost_class: str
    purchase_unit: str
    usage_unit: str
    fabric_width_cm: float | None = None
    fabric_family: str | None = None        # NEW — nullable

class MaterialOut(MaterialBase):
    id: UUID
    current_avg_cost: float
    reorder_min_qty: float | None = None
    is_archived: bool
    created_at: datetime
    updated_at: datetime
    current_total_qty: float | None = None

class CreateMaterialRequest(MaterialBase):
    pass  # fabric_family inherited from MaterialBase

class PatchMaterialRequest(BaseModel):
    name: str | None = None
    reorder_min_qty: float | None = None
    is_archived: bool | None = None
    fabric_width_cm: float | None = None
    fabric_family: str | None = None        # NEW — nullable, None = tidak diubah
```

Catatan untuk `PATCH`: `None` berarti "tidak diubah". Untuk menghapus family (set null), iOS perlu kirim `"fabric_family": null` secara eksplisit — Pydantic default behavior sudah handle ini dengan `model_validate(data, from_attributes=True)`. Konfirmasi behavior null vs absent di implementation.

## Router Changes

### `routers/materials.py`

**`GET /materials`** — tidak ada perubahan kode; `MaterialOut` sudah include `fabric_family` setelah schema update. Query SQLAlchemy sudah select semua kolom dari `material` table — kolom baru otomatis terpick.

**`POST /materials`** — tidak ada perubahan kode; `CreateMaterialRequest` sudah include `fabric_family`.

**`PATCH /materials/{material_id}`** — tidak ada perubahan kode selain schema. Implementasi PATCH biasanya `for field, value in body.model_dump(exclude_unset=True).items(): setattr(db_material, field, value)` — otomatis handle `fabric_family`.

**`GET /materials/families`** — endpoint baru:

```python
@router.get("/families", response_model=list[str])
async def get_fabric_families(
    db: AsyncSession = Depends(get_db),
    owner: OwnerAccount = Depends(get_current_owner),
):
    """Return distinct non-null fabric_family values for this owner, sorted alphabetically."""
    result = await db.execute(
        select(Material.fabric_family)
        .where(
            Material.owner_id == owner.id,
            Material.fabric_family != None,
            Material.is_archived == False,
        )
        .distinct()
        .order_by(Material.fabric_family)
    )
    return [row[0] for row in result.all()]
```

Response: `["Nilon", "Satin", "Waffle"]`

**Route order penting:** `GET /materials/families` harus didaftarkan SEBELUM `GET /materials/{material_id}` agar `/families` tidak di-parse sebagai UUID. Di FastAPI dengan router prefix `/materials`, pastikan:
```python
router.get("/families", ...)       # dulu
router.get("/{material_id}", ...)  # setelahnya
```

## Validation

Tidak ada business rule khusus untuk `fabric_family`:
- Tidak perlu unique constraint
- Tidak perlu referential integrity (free text)
- Nilai apa pun yang non-empty diterima (backend trim whitespace sebelum simpan untuk konsistensi)

```python

if material.fabric_family:
    material.fabric_family = material.fabric_family.strip() or None
```

## Deployment Order

1. Deploy migration (ALTER TABLE) → tidak breaking
2. Deploy backend code (schema + endpoint baru) → tidak breaking (nullable field)
3. iOS release/update → mulai kirim/terima `fabric_family`

Backend bisa deploy dulu tanpa iOS update. iOS lama akan ignore field baru (JSON decode dengan `Optional` = tidak crash). Tidak ada coordination window yang sempit.
