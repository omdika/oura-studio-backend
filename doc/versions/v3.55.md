# Version 3.55 - Fix Timezone GMT+0 vs GMT+7 (WIB) pada Query Filter Tanggal & Dashboard

## 1. Problem / Opportunity
*   **Context:** Data transaksi penjualan (`sales_order.sold_at`) dan log lainnya disimpan di database Supabase dengan format `TIMESTAMPTZ` berbasis UTC (`+00`). Namun, saat filter rentang tanggal (`from` dan `to`) atau perhitungan `today` pada dashboard dijalankan di backend FastAPI, query mengombinasikan tanggal dengan `00:00:00 UTC`.
*   **Contoh Masalah:** Transaksi tanggal `2026-09-12 23:50:13 UTC` setara dengan `2026-09-13 06:50:13 WIB` (GMT+7). Ketika user menyaring filter tanggal `13 September 2026` s/d `13 September 2026`, backend mencari range `2026-09-13 00:00:00 UTC` s/d `2026-09-14 00:00:00 UTC`. Hal ini menyebabkan transaksi pukul 06:50 WIB tersebut terlewat/tereliminasi dari hasil pencarian karena dianggap tanggal `2026-09-12`.
*   **Objective:** Menyelaraskan seluruh boundary query rentang tanggal di backend FastAPI agar mengacu pada zona waktu lokal WIB (GMT+7 = UTC+7). Rentang kalender `13 September 2026` di WIB dikonversi menjadi `2026-09-12 17:00:00 UTC` s/d `2026-09-13 17:00:00 UTC`.

## 2. Helper Timezone & Boundary Calculation (`app/utils/timezone.py`)

Membuat helper terpusat `app/utils/timezone.py`:
```python
from datetime import date, datetime, timedelta, timezone

WIB = timezone(timedelta(hours=7))

def get_wib_day_bounds(date_from: date, date_to: date) -> tuple[datetime, datetime]:
    """
    Mengonversi tanggal kalender WIB (from & to) menjadi boundary datetime UTC.
    Contoh: 13 Sept 2026 s/d 13 Sept 2026 (WIB) ->
    start_utc = 2026-09-12 17:00:00 UTC
    end_utc   = 2026-09-13 17:00:00 UTC
    """
    start_wib = datetime.combine(date_from, datetime.min.time(), tzinfo=WIB)
    end_wib = datetime.combine(date_to, datetime.min.time(), tzinfo=WIB) + timedelta(days=1)
    return start_wib.astimezone(timezone.utc), end_wib.astimezone(timezone.utc)

def get_wib_today_bounds() -> tuple[datetime, datetime, date]:
    """
    Mendapatkan boundary UTC untuk hari ini di zona waktu WIB.
    Returns: (day_start_utc, day_end_utc, today_wib_date)
    """
    now_wib = datetime.now(timezone.utc).astimezone(WIB)
    today_wib = now_wib.date()
    day_start_utc, day_end_utc = get_wib_day_bounds(today_wib, today_wib)
    return day_start_utc, day_end_utc, today_wib

def get_wib_month_start_bounds() -> tuple[datetime, datetime, date]:
    """
    Mendapatkan boundary UTC untuk awal bulan sampai akhir hari ini di WIB.
    """
    now_wib = datetime.now(timezone.utc).astimezone(WIB)
    today_wib = now_wib.date()
    month_start_wib = today_wib.replace(day=1)
    month_start_utc, day_end_utc = get_wib_day_bounds(month_start_wib, today_wib)
    return month_start_utc, day_end_utc, today_wib
```

## 4. API Router Adjustments (FastAPI Backend)

### 4.1 `GET /sales-orders` (`app/routers/sales.py`)
Gunakan `get_wib_day_bounds(from_, to)` untuk menyaring `SalesOrder.sold_at`:
```python
if from_ is not None or to is not None:
    start_date = from_ or date.min
    end_date = to or date.max
    start_utc, end_utc = get_wib_day_bounds(start_date, end_date)
    if from_ is not None:
        q = q.filter(SalesOrder.sold_at >= start_utc)
    if to is not None:
        q = q.filter(SalesOrder.sold_at < end_utc)
```

### 4.2 `GET /reports/dashboard` (`app/routers/reports.py`)
Gunakan `get_wib_today_bounds()` dan `get_wib_month_start_bounds()`:
```python
day_start, day_end, today_wib = get_wib_today_bounds()
month_start, _, _ = get_wib_month_start_bounds()
```
